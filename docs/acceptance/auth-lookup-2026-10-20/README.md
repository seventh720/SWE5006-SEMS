# 鉴权查询精简与本地对比

日期：2026-10-20，SGT。基于已合并的 `main 7b46634`，分支 `perf/lean-current-permissions`。维护者要求先优化代码，保持业务逻辑，不调整服务器。本次没有部署分支或修改云端配置。

## 改动与行为

JWT 校验原先通过 `findById` 加载完整 `UserAccount` 和角色，包括密码哈希、个人资料和头像。现在采用 [JPQL DTO 投影](https://docs.spring.io/spring-data/jpa/reference/repositories/projections.html)，只选择账号 ID 和角色，并在数据库中筛选 ACTIVE 状态。实际 SQL 从每行 16 列缩减为 2 列；前后均为一次查询，没有减少 SELECT 次数。

鉴权服务不再为这一条纯标量 SELECT 单独创建显式事务。Spring Data 的[声明查询默认不添加事务](https://docs.spring.io/spring-data/jpa/reference/3.5/jpa/transactions.html)，账号状态与角色在同一条 SQL 中读取，采用 PostgreSQL 的[语句快照](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-READ-COMMITTED)；没有拆成先读状态、再读角色的两个操作。实际调用来自 JWT 转换器、位于控制器业务事务之前；业务写入事务和锁保持原样。

每次认证仍查询数据库，没有引入权限缓存。JWT 声明与当前数据库角色的交集规则保持原样：撤权立即生效，新增权限仍需重新登录，LOCKED、DISABLED、删除账号仍拒绝认证。左连接保留有效账号没有角色行时的空权限集合语义。API、预订事务、库存锁、幂等、核销规则和密码算法均未修改，也没有数据库迁移。

## 本地测量

环境：JDK 21.0.12、Spring Boot 3.5.16、Testcontainers PostgreSQL 17 Alpine；本机 Docker 可用 10 CPU、约 7.75 GiB 内存。应用测试 JVM 与容器数据库通过本机端口通信，开启 JaCoCo；没有施加云端资源上限，没有经过 HTTP、反向代理或浏览器。

使用一个合成 ATTENDEE 账号，与此前容量测试的普通用户角色一致。分别测试无头像和约 100 KiB 的合成头像文本；后者仅为读取负载，不验证图片上传。旧路径保留原来的完整实体读取与独立只读事务；新路径为单条自动提交 SELECT。每种头像设置先各预热 200 次，再交替顺序运行 5 轮、每轮各 500 次，共各 2500 个计时样本。计时包含对应路径的事务/连接处理、数据库读取和结果映射，排除准备数据和断言；无耗时通过门槛。

22:05 SGT 测量结果，单位 ms：

| 账号数据 | 路径 | 平均 | 中位数 | p95 |
|---|---|---:|---:|---:|
| 无头像 | 原完整实体 | 0.300 | 0.278 | 0.392 |
| 无头像 | 精简投影 | 0.153 | 0.142 | 0.185 |
| 100 KiB 头像 | 原完整实体 | 0.432 | 0.378 | 0.690 |
| 100 KiB 头像 | 精简投影 | 0.158 | 0.132 | 0.281 |

本轮平均耗时分别下降约 49% 和 63%。这是单一鉴权读取的本地诊断，样本受 JIT、缓存、调度和测量顺序影响，两个头像场景不能直接相互比较；这些比例不是端到端接口或并发容量提升比例。优化同时减少传输字段、完整用户实体创建和单次读取的显式事务开销。

复现命令（JDK 21、Docker 已启动）：

```bash
DEBUG=false RUN_CONTAINER_TESTS=true mvn -f backend/pom.xml \
  -Dtest=UserAccessIntegrationTest -Dsems.auth-lookup-benchmark=true test
```

`DEBUG=false` 避免继承本机同名环境变量而启用 Spring SQL 调试输出。对比测试默认跳过，不在 CI 中对噪声敏感的耗时设断言；四项功能/SQL 回归在容器集成测试中正常执行。
