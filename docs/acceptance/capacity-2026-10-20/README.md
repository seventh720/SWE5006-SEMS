# 云端分级容量测试

2026-10-20，SGT。目标`https://swe5006.seventh720.com`，受测版本始终为`60c9430da89b960df59805afd65e76478e052884`。维护者授权在现有2 vCPU/3832 MiB共享云主机测试，随后分别授权取消负载均值阻断、让延迟仅参与成绩判定。

**1000 VU未执行，不能宣称千并发达标。** 50/100 VU仅通过短时读取场景；250 VU完整档活动列表p95超标；500 VU出现真实8秒请求超时后停止。此次没有测出最大容量，也不能仅凭这些结果认定具体代码缺陷。

## 三次尝试

| 尝试 | 配置与结果 | 停止原因 |
|---|---|---|
| [第一轮](first-run.md)，20:27–20:32 | 50/100 VU短时读通过；250 VU只运行约10秒稳定档 | 主机load1>8连续3次；触发时12.04 |
| 第二轮，21:00–21:02 | 取消load1阻断，250 VU完整跑完；活动列表稳定档p95 **4.61秒**，HTTP错误率0 | 单接口p95未满足3秒门槛，退出99 |
| 第三轮，21:18 | 延迟只记成绩，从500 VU续测；**169个请求在8秒内未完成** | 全程错误率 **1.01%**，触发保留的错误率停止条件 |

3秒来自proposal的“95%常见请求3秒内”目标，不是所有请求必须小于3秒，也不是超过就代表系统崩溃。第三轮即使取消延迟阻断，仍保留健康、内存、OOM及明显请求错误的停止条件；此次最终停止由请求错误触发。

## 第二轮：完整250 VU档

先低速准备1000个独立参与者账号与1个临时ORGANIZER，再创建10个分散活动及1个限额活动。每个VU使用正式登录得到的独立JWT，顺序读取活动列表、活动详情、本人资料、本人订单，之后等待1秒。1 VU读写预检通过；读取从上一轮未完成的250档续测，30秒爬升、30秒稳定档。

共18516个请求，全程平均294.23 req/s；整体稳定档p95约963.66 ms，但活动列表单接口p95为4610.77 ms，不能用整体数字遮蔽该接口失败。HTTP状态及内容检查均无错误。主机负载峰值14.43，未因load1停止；有一轮SWE5006健康探针失败，下一轮恢复，未连续触发健康停止条件。没有容器OOM/重启，数据库采样没有锁等待；尚未确定慢请求根因。

证据：[运行](without-load-limit/run.json)、[250 VU摘要](without-load-limit/read-250vu.json)、[资源](without-load-limit/resource-summary.json)。

## 第三轮：500 VU实际超时

复用第二轮已通过预检的账号/活动，从500档开始；延迟阈值保留为失败成绩，但不会单独阻止后续档位。错误率、健康和资源保护继续生效。计划仍为爬升30秒、稳定档30秒，再尝试1000档180秒。
