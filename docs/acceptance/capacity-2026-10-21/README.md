## 环境与负载模型

- 原2 vCPU、3832 MiB共享云主机，SWE5001继续运行。后端768 MiB、数据库512 MiB、前端96 MiB上限不变。未升级服务器，未改变业务、权限或库存逻辑。
- k6 1.3.0从本机Docker运行，生成器限制4 CPU/2 GiB；测试期间抑制本机空闲睡眠。500轮使用500个独立参与者和1个专用组织者；1000轮新建1000个独立参与者和1个专用组织者。仅给本轮组织者临时ORGANIZER，不授予ADMIN。每轮新建10个分散活动及1个100票竞争活动。
- 注册/登录低速准备，不计入压力成绩。每次读取迭代依次GET活动列表、活动详情、本人资料、本人订单，再等待1秒。混合场景每五轮增加订票→读票→取消，每VU最多60次；各VU分配至10个活动之一。
- 先1 VU读取及混合预检。500轮读取250→500，混合50→100→250→500；1000轮计划读取直接验证1000，再混合50→100→250→500→1000；实际在读取档停止。读取/混合每档爬升30秒，低档保持30秒，目标档保持180秒，档间恢复10秒；每轮唯一幂等命名空间。最后配置目标人数各提交一次热门活动订票请求，最长60秒。
- p95＜3秒用于整体及逐接口评分；延迟不达标照实记失败，但允许继续后续档位。8秒请求超时、真实错误、`checks: rate==1`及健康/内存/OOM/监控断线保护保持原样；load1只记录。健康失败或耗时＞2秒连续3样本、可用内存＜384 MiB、容器内存使用＞95%等条件仍会停止测试。
