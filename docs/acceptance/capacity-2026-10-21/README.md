## 502定位与待部署修正

Caddy日志精确记录41次502：23次上游EOF、18次连接被重置，上游地址属于SEMS前端。相同窗口前端Nginx有12条`1024 worker_connections are not enough, reusing connections`告警，后端没有WARN/ERROR。云端每工作进程连接名额1024，继承文件软上限1024、硬上限524288。[NGINX说明](https://nginx.org/en/docs/ngx_core_module.html#worker_connections)指出连接名额包含客户端及上游连接，并受文件句柄上限约束。证据指向前端连接名额耗尽后回收持久连接，未逐一把41次失败关联到单条Nginx告警；摘要见[失败定位](1000/proxy-failure-summary.json)。

修正在前端镜像显式使用`nginx-main.conf`，设置`worker_connections 4096`、`worker_rlimit_nofile 8192`。其余Nginx主配置与当前云端默认值逐项归一化比较一致；原API/健康上游连接池、URI/鉴权/来源转发和安全头不变。没有提高CPU/容器内存额度，也未改变业务或库存逻辑。连接管理结构及高峰连接的内存/文件句柄占用可能增加，前端仍受96 MiB内存上限约束，须在部署后的同口径复测中观察实际资源占用。

隔离回归使用相同镜像、单工作进程、96 MiB内存及继承1024/524288文件限制，保持1200条客户端连接，以32路请求建立后再逐条复用。旧配置可复现`RemoteDisconnected`；新配置1200条连接ID全部保持不变，20次API/健康请求的鉴权、路径、来源及上游复用检查也通过。该测试证明连接回收问题可在本地消除，不表示1200个业务请求同时在途，也不能替代云端1000 VU完整复测。[对照结果](proxy-capacity-regression.json)、[通过日志](proxy-capacity-fixed.txt)。

**连接额度修正尚未部署，当前1000 VU成绩仍为未通过。** 合并部署后需先验证前端实际连接/文件限制，再按同口径复测；本轮未继续热改云端或加压。
