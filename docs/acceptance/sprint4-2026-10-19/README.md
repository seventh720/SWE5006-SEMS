# Sprint 4 浏览器过程验收

时间：2026-10-19 12:36–12:43 SGT。
环境：Chrome 实际页面操作，localhost:13000 生产前端构建；独立 PostgreSQL 测试库；Spring Boot 后端。账号仅为本次虚构测试账号。账号与角色通过 API 准备，以下业务步骤通过浏览器控件完成，未用接口调用替代业务操作。

## 已验证

1. Organizer 创建活动、配置免费票、发布活动。
2. Manage staff 分配 browser_staff，列表显示1人；Staff 通知页出现分配通知。
3. Attendee 预订2张票，订单详情进入 View tickets；两张不同 QR 成功加载（各320×320）。
4. Staff 选择已分配活动，手动输入从票券页面读取的凭证；预检 VALID，再确认核销成功，审计记录显示操作员及时间。
5. 再次验同一票显示 CHECKED_IN，确认核销按钮禁用；票券页面刷新后已核销票不再展示 QR。
6. Organizer 统计：有效预订2、取消0、有效签到1。
7. Attendee 取消包含已核销票的订单被拒绝，页面明确显示原因。
8. Organizer 修改地点，Staff 通知页显示原地点→新地点。
9. 撤销 Staff，收到撤权通知，Staff 工作台不再有活动且不能验票；重新分配后恢复。
10. 新建另一笔1张票订单，修正后的确认页显示电子票已准备好并提供 View tickets。个人取消成功，票券显示 Voided，无 QR。
11. Organizer 取消活动，Staff 收到活动取消通知；原2张票均 Voided，已核销历史保留。
12. 最终统计：有效预订0、取消3、有效签到0。旧票码在已取消活动中被后端拒绝。
13. 用其他账号打开参与者票券页面，显示订单不可用或不属于本人，没有 QR。
14. 参与者及组织者页面记录的浏览器 error 日志为空（预期业务拒绝通过页面提示验收）。

## 发现并修复

- 订票成功页面仍显示“电子票后续版本提供”：已改为票券准备完成，并添加直接查看票券入口。最终前端构建已通过真实页面再次订票验证。
- 取消活动验票提示误导为时间窗口不符：后端分离活动状态与时间窗口错误，提示活动未发布、不可签到。
- PR #26 review 的 Clock 建议：核销与票券作废改为应用层注入 Clock，实体接收明确时间；固定时间断言验证 checkedInAt、voidedAt。不会改变授权或时段规则。
