## 2. Sprint Goal 与范围

**Sprint Goal：组织者能够创建、修改并发布自己的活动；用户能够浏览已发布活动及详情；系统保证草稿不可被普通用户读取，组织者无法操作他人的活动。**

与 Sprint 1 的衔接：管理员为已注册用户分配 `ORGANIZER` → 用户重新登录获得新角色令牌 → 创建活动草稿 → 发布活动 → 其他用户浏览。角色令牌刷新按现有机制处理，不假设角色变更会立即更新已签发 JWT。

### 本轮必须交付

- 活动草稿创建、列表、详情与编辑。
- 活动发布与取消；已发布活动本轮不支持编辑，取消后不可恢复。
- 面向用户的已发布活动列表与详情，分页及标题关键词查询。
- 组织者“我的活动”页面、表单、发布和取消操作。
- 后端角色及活动归属校验、数据库迁移、自动化测试和端到端演示。

### 有余量再做

- 按活动时间筛选。
- 下一轮票种模型和接口契约设计，仅输出设计文档。

### 后续迭代

实际票种售卖、库存扣减、预订、支付、退款、二维码票券、签到、邮件通知、报表及图片上传。本轮活动容量只是信息字段，不承诺库存或防超卖功能。

## 3. 用户故事与验收标准

| 编号 | 用户故事 | 可验收结果 |
|---|---|---|
| US-201 | 作为组织者，我希望保存活动草稿，以便准备活动信息 | 合法请求返回活动 ID 和 `DRAFT`；刷新或重启后仍能读取；创建者由当前登录用户确定，不能由请求伪造 |
| US-202 | 作为组织者，我希望查看和编辑自己的草稿 | “我的活动”仅返回本人活动；本人可编辑草稿；其他组织者不能读取管理详情、修改、发布或取消该活动 |
| US-203 | 作为组织者，我希望发布准备完成的活动 | 满足必填项且开始时间晚于当前时间才可发布；成功后普通用户可浏览；重复发布返回明确的状态冲突 |
| US-204 | 作为组织者，我希望取消活动 | 本人草稿或已发布活动可转为 `CANCELLED`；公开列表移除，公开详情不可访问；管理端仍保留记录；不能恢复或重新发布 |
| US-205 | 作为用户，我希望浏览活动并查看详情 | 列表只包含 `PUBLISHED`；支持分页、标题关键词、空结果提示；详情展示名称、描述、地点、时间和容量；草稿或取消活动 ID 不泄露详情 |
| US-206 | 作为团队，我希望新增业务不破坏原有能力 | 注册、登录、当前用户、管理员用户查询和角色分配回归通过；新建数据库及 Sprint 1 数据库升级均成功；三项必需 CI 通过 |

建议允许未登录访客浏览公开活动，降低首次使用门槛；这是本轮新增产品约定，D1 确认。若团队选择登录后浏览，保留现有认证边界，并同步修改接口、前端路由和验收用例。

## 6. 业务与技术约定（D1 冻结）

### 活动模型

建议 `events` 包含 `id`、`organizer_id`、`title`、`description`、`location`、`starts_at`、`ends_at`、`capacity`、`status`、`version`、`created_at`、`updated_at`。

- 时间字段存储带时区时间，API 使用含时区的 ISO 8601，界面明确展示时区；开始时间必须早于结束时间，发布时开始时间必须晚于当前时间。
- 标题、描述和地点不能为空；D1 确定长度上限；容量为正整数。前后端采用一致规则，后端是最终校验点。
- 草稿同样保存完整合法字段，本轮不实现部分表单自动保存。
- `organizer_id` 来自 JWT 当前用户标识；跨模块只通过公开应用接口或 ID 引用，不引入 `identity` 的内部实体或 Repository。
- 使用乐观锁或等价的条件更新避免编辑、发布和取消的并发覆盖；冲突返回 `409`。
- 状态仅允许 `DRAFT → PUBLISHED`、`DRAFT → CANCELLED`、`PUBLISHED → CANCELLED`；其他转换返回 `409`。保留记录，不增加物理删除接口。

### 权限矩阵

| 操作 | 未登录 / 普通用户 | ORGANIZER | ADMIN |
|---|---|---|---|
| 公开列表、公开详情 | 只读已发布活动（按公开浏览建议） | 同左 | 同左 |
| 创建活动 | 不允许 | 允许，归属本人 | 允许，归属本人 |
| 管理列表及详情 | 不允许 | 仅本人 | 仅本人 |
| 编辑草稿、发布、取消 | 不允许 | 仅本人，且状态合法 | 仅本人，且状态合法 |

本轮不增加管理员跨组织者代管功能。`STAFF` 单独角色不授予活动写权限；多角色账号按其拥有的组织者或管理员权限处理。管理接口未登录返回 `401`，角色不符返回 `403`，对象不存在或不属于本人返回 `404`；公开详情对草稿和取消活动统一返回 `404`。

### 建议 API

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/events?page=0&size=10&keyword=...` | 公开活动列表，固定只查询已发布状态 |
| GET | `/api/v1/events/{id}` | 公开活动详情 |
| GET | `/api/v1/organizer/events` | 本人管理列表，包含草稿、已发布及取消状态 |
| GET | `/api/v1/organizer/events/{id}` | 本人管理详情 |
| POST | `/api/v1/organizer/events` | 创建草稿，成功返回 `201` |
| PUT | `/api/v1/organizer/events/{id}` | 修改草稿 |
| POST | `/api/v1/organizer/events/{id}/publish` | 发布 |
| POST | `/api/v1/organizer/events/{id}/cancel` | 取消 |

公开与管理列表均使用分页；默认每页 10 条，上限建议 50 条，非法分页参数返回 `400`。公开列表按开始时间升序、ID 作为稳定次序；管理列表按创建时间降序、ID 作为稳定次序。列表响应统一为 `items`、`page`、`size`、`totalElements`、`totalPages`。

如采纳公开浏览，只放行公开活动列表及详情的 **GET** 请求，其他接口仍需认证；前端浏览页面移出 `ProtectedRoute`，管理页面继续受保护。沿用现有 `ApiError` / Problem 响应形式，覆盖 `400/401/403/404/409`，管理请求携带 JWT。

## 7. 测试重点与完成定义

### 必测场景

1. 组织者 A 创建、编辑、发布活动；用户能看到发布结果。
2. 组织者 B 使用 A 的活动 ID 尝试查询管理详情、编辑、发布或取消，全部被拒绝。
3. 普通用户和仅有 `STAFF` 角色的用户不能创建或管理活动；未登录管理请求被拒绝。
4. 草稿及取消活动不能从公开列表或直接详情 URL 读取。
5. 缺少字段、非正容量、结束早于开始、已过期活动发布均被拒绝；重复发布和取消后发布返回冲突。
6. 编辑与发布并发时，不出现已发布内容被过期编辑请求覆盖。
7. 搜索、分页、无结果、失败重试、令牌过期和表单错误提示符合预期。
8. 空 PostgreSQL 执行全部迁移成功；已有 Sprint 1 数据库升级后用户及角色数据保留。
9. 注册、登录、`/auth/me`、管理员用户查询和角色分配回归通过。

### Definition of Done

- 用户故事的验收标准通过，功能使用真实数据库与后端，不依赖演示假数据。
- 相关单元测试、PostgreSQL 集成测试和前端交互测试覆盖上述关键风险。
- 按现有规范执行后端 `mvn verify`、`RUN_CONTAINER_TESTS=true mvn test`，前端 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`，记录实际结果。
- `backend`、`backend-integration`、`frontend` 三项 CI 通过；Telegram 通知不作为验收门槛。
- PR 获得至少一名其他组员批准；相关审查讨论解决，按团队流程合并。
- 新增 Flyway 迁移、业务代码、测试、ERD 与数据字典一并提交；不修改已执行迁移。
- README 包含新功能入口、接口说明、启动步骤和演示步骤；UI PR 附截图。
- 无阻断主流程、越权或数据损坏的未解决缺陷；其余缺陷登记负责人和后续安排。

## 8. Sprint Review 演示脚本

1. 使用 Sprint 1 注册功能准备组织者 A、组织者 B 和普通用户三个账号；管理员授予前两者 `ORGANIZER`，二者重新登录。
2. A 创建一个未来举行的活动草稿，修改地点；“我的活动”可见，公开列表不可见。
3. A 发布活动；普通用户在列表搜索到活动，并打开详情。
4. B 尝试通过 A 的活动 ID 编辑和取消，展示后端拒绝结果。
5. A 取消活动，展示公开列表及详情不再提供该活动，管理端保留取消记录。
6. 展示测试、数据库迁移和 CI 结果，记录每条用户故事是否验收通过。
