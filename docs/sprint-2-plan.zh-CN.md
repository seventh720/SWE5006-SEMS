# Sprint 2 历史需求与验收标准

保留原计划中的用户故事、验收标准和DoD，供报告追溯；这些是当时的目标，不是实际完成记录。负责人占位、估算、建议排期及重复技术方案已删去，完整原计划可从Git历史查看。当前实现见[接口说明](sprint-3-api.zh-CN.md)，实际结果见[验收索引](acceptance/README.md)。

## 用户故事与验收标准

| 编号 | 用户故事 | 可验收结果 |
|---|---|---|
| US-201 | 作为组织者，我希望保存活动草稿，以便准备活动信息 | 合法请求返回活动 ID 和 `DRAFT`；刷新或重启后仍能读取；创建者由当前登录用户确定，不能由请求伪造 |
| US-202 | 作为组织者，我希望查看和编辑自己的草稿 | “我的活动”仅返回本人活动；本人可编辑草稿；其他组织者不能读取管理详情、修改、发布或取消该活动 |
| US-203 | 作为组织者，我希望发布准备完成的活动 | 满足必填项且开始时间晚于当前时间才可发布；成功后普通用户可浏览；重复发布返回明确的状态冲突 |
| US-204 | 作为组织者，我希望取消活动 | 本人草稿或已发布活动可转为 `CANCELLED`；公开列表移除，公开详情不可访问；管理端仍保留记录；不能恢复或重新发布 |
| US-205 | 作为用户，我希望浏览活动并查看详情 | 列表只包含 `PUBLISHED`；支持分页、标题关键词、空结果提示；详情展示名称、描述、地点、时间和容量；草稿或取消活动 ID 不泄露详情 |
| US-206 | 作为团队，我希望新增业务不破坏原有能力 | 注册、登录、当前用户、管理员用户查询和角色分配回归通过；新建数据库及 Sprint 1 数据库升级均成功；三项必需 CI 通过 |

## 测试重点与完成定义

### 必测场景

1. 组织者 A 创建、编辑、发布活动；用户能看到发布结果。
2. 组织者 B 使用 A 的活动 ID 尝试查询管理详情、编辑、发布或取消，全部被拒绝。
3. 普通用户和仅有 `STAFF` 角色的用户不能创建或管理活动；未登录管理请求被拒绝。
4. 草稿及取消活动不能从公开列表或直接详情 URL 读取。
5. 缺少字段、非正容量、结束早于开始、已过期活动发布均被拒绝；重复发布和取消后发布返回冲突。
6. 编辑与发布并发时，不出现已发布内容被过期编辑请求覆盖。
7. 搜索、分页、无结果、失败重试、令牌过期和表单错误提示符合预期。
8. 空 PostgreSQL 执行全部迁移成功；已有 Sprint 1 数据库升级后用户及角色数据保留。
9. 注册、登录、`/auth/me`、管理员用户查询和角色分配回归通过。

### Definition of Done

- 用户故事的验收标准通过，功能使用真实数据库与后端，不依赖演示假数据。
- 相关单元测试、PostgreSQL 集成测试和前端交互测试覆盖上述关键风险。
- 按现有规范执行后端 `mvn verify`、`RUN_CONTAINER_TESTS=true mvn test`，前端 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`，记录实际结果。
- `backend`、`backend-integration`、`frontend` 三项 CI 通过；Telegram 通知不作为验收门槛。
- PR 获得至少一名其他组员批准；相关审查讨论解决，按团队流程合并。
- 新增 Flyway 迁移、业务代码、测试、ERD 与数据字典一并提交；不修改已执行迁移。
- README 包含新功能入口、接口说明、启动步骤和演示步骤；UI PR 附截图。
- 无阻断主流程、越权或数据损坏的未解决缺陷；其余缺陷登记负责人和后续安排。
