# 通知界面与接入约定

更新：2026-10-20。站内通知已包含订单、活动、开售提醒、STAFF分配/撤销及角色变化，均已接入持久化和相关业务事务。

## 前端

- 登录后从Dashboard或STAFF工作台的Notifications进入 `/notifications`。
- 支持未读数量、全部/未读筛选、分页、刷新、单条标记已读及关联页面跳转。
- 默认启用。若临时部署到未升级的旧后端，可配置 `VITE_NOTIFICATIONS_ENABLED=false` 并重新构建关闭；正常部署需同时更新前后端，Flyway自动创建notifications表。
- 当前是站内通知，打开入口/列表、回到窗口或点击刷新时加载；页面打开时每30秒刷新。不包含邮件、浏览器推送或WebSocket，关闭页面仍会在服务端生成通知，下次进入可读取。

## 已实现接口

| 方法与路径 | 返回/行为 |
|---|---|
| GET `/api/v1/notifications?page=0&size=10&unreadOnly=false` | `{items, totalPages, unreadCount}`；按createdAt倒序、id稳定排序；unreadCount为当前用户全部未读总量，不随分页改变 |
| POST `/api/v1/notifications/{id}/read` | 幂等标记本人通知为已读，成功204 |

每条通知：`id, type, title, message, createdAt, readAt`，以及可选的`eventId, bookingId, ticketTypeId`。时间为含时区ISO8601；未读时readAt为null。消息提供发生时的必要上下文和变更前后内容，不包含证件或敏感报名资料。

所有登录角色可访问自己的通知。后端从JWT取得接收者，列表必须按本人过滤；读取/更改他人通知返回404。通知链接不能替代目标页面的权限校验。

## 类型与触发

| type | 触发与接收者 | 页面跳转 |
|---|---|---|
| ROLES_CHANGED | 管理员实际修改角色时通知该用户；无变化不重复发送，通知失败回滚角色修改 | 通知列表；新权限需重新登录 |
| STAFF_ASSIGNED | 已接入：组织者实际新增活动授权时通知该工作人员 | STAFF工作台，可选择本人已获授权活动 |
| STAFF_REVOKED | 已接入：组织者实际撤销活动授权时通知该工作人员 | 不提供已撤销活动的操作入口 |
| BOOKING_CONFIRMED | 免费订单首次确认，通知订票人 | 本人订单 |
| BOOKING_CANCELLED | 订单取消，包括活动取消联动，通知订票人 | 历史订单 |
| REGISTRATION_OPENING_SOON | 预约活动开始报名/开售前5分钟，通知仍有效的预约用户 | 我的预约；仍需手动确认订票，不占库存 |
| EVENT_UPDATED | 已发布活动标题、时间、地点、报名窗口或描述变更，通知有效订票人、未转订单预约用户，按用户去重；已分配的有效STAFF同样接收 | 有bookingId时进订单，否则活动详情 |
| EVENT_CANCELLED | 活动取消，通知未转订单的预约用户；订票人通过订单取消通知获知；已分配的有效STAFF同样接收 | 只展示取消内容，避免打开已隐藏的公开活动 |

“前5分钟”目前按 `registrationOpensAt` 定义，不是活动开始时间。不要把提醒理解为自动抢票或预订成功。

## 定时与一致性

- 后端每30秒查询 `registrationOpensAt - 5分钟 ≤ 当前时间 < registrationOpensAt` 的有效预约，不依赖浏览器开着。健康运行时进入窗口后通常在一个扫描周期内生成，不承诺精确到秒；前端轮询还可能增加一个刷新周期。
- 创建预约时已经进入5分钟窗口，可立即生成一次提醒；开售时间为空或已经开售则不生成此类提醒。
- 已删除、已订票、活动已取消、报名已截止的预约不生成提醒；服务停机跨过开售时间，不补发过期的“即将开售”提示。
- 提醒按接收者、预约ID及开售时间去重；开售时间调整后重新按新时间计算，发送前再核对最新状态。普通事件按业务操作/版本及接收者去重，不能因为请求重放重复通知。
- 订票/取消/活动调整的通知记录与业务修改同事务提交；业务回滚不得留下成功通知。定时任务并发也需数据库唯一约束防重。
- 定时处理与预约新增/删除、订票、活动修改/取消共用活动锁，拿锁后重新核对窗口和接收者。已发出的消息作为历史保留，变更/取消另发通知；提醒文案包含具体开售日期时间。

配置：`sems.notifications.reminders-enabled=false` 可停止定时扫描，`sems.notifications.reminder-delay-ms` 默认30000。测试关闭后台扫描并直接调用事务服务，以固定时钟验证边界。保存窗口内预约的即时提醒仍执行。

## STAFF分配与撤销（2026-10-19 已接入）

组织者从“活动详情 → Manage staff”查看当前分配、选择可用 STAFF、分配及移除。管理员先授予账号 STAFF 角色；组织者不能通过此页修改全局角色。仅展示用户名，不暴露邮箱或个人资料。

- GET /api/v1/staff/events/{eventId}/assignments：校验活动归属后返回活动名称、可用人员及已分配人员。
- PUT /api/v1/staff/events/{eventId}/assignments/{staffId}：分配有效 STAFF 账号，成功返回 204。
- DELETE 同一路径：撤销，成功返回 204。

授权变更先锁活动；只有 INSERT/DELETE 实际改变一行时，才调用 NotificationDeliveryService.staffAssignment。每次实际变更生成新的操作标识；重复分配或重复撤销不发通知，撤销后重新分配会发送新通知。通知与授权处于同一事务，通知写入失败会回滚授权。

活动调整/取消已通过 StaffAssignmentService 查询有效已分配人员，加入现有同步通知监听器。活动调整按用户去重，优先保留订单链接；取消时同时持有有效订单的 Staff 通过订单取消通知获知，其他 Staff 接收活动取消通知。

集成测试覆盖5分钟边界、重复/并发执行、开售时间变化、窗口内新增预约、已订票/删除预约、活动取消、事务回滚、已读幂等及跨用户隔离。前端测试覆盖列表、标记已读、筛选、失败与重新登录；授权集成测试还覆盖目录隔离、通知去重、重新分配及通知失败时的事务回滚。云端结果见[验收记录](acceptance/sprint4-2026-10-20/README.md)，测试范围和边界见[测试记录](testing.zh-CN.md)。
