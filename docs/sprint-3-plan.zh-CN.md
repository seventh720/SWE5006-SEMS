# Sprint 3 历史需求与验收标准

保留原计划中的用户故事、验收标准和DoD，供报告追溯；这些是当时的目标，不是实际完成记录。负责人占位、估算、建议排期及重复技术方案已删去，完整原计划可从Git历史查看。当前实现见[接口说明](sprint-3-api.zh-CN.md)，实际结果见[验收索引](acceptance/README.md)。

## 用户故事与验收标准

| 编号 | 用户故事 | 可验收结果 |
|---|---|---|
| US-301 | 组织者配置本人活动票种 | 可创建及修改票种；价格非负、配额为正；总配额不超过容量；他人和仅 STAFF 账号操作被拒绝 |
| US-302 | 参与者查看票种并预订 | 匿名可浏览已发布活动票种，预订需 ATTENDEE；只有未来开始的已发布活动、免费且库存足够的票种可以下单；返回订单及服务端金额 |
| US-303 | 多人同时预订有限库存 | 最后 1 张票的并发请求最多成功 1 个；失败请求不留有效订单或扣减；总有效预订数量不超过配额 |
| US-304 | 参与者查看自己的订单 | 分页列表及详情展示活动、票种、数量、金额、状态；刷新和重启后保留；其他参与者不能访问该订单 |
| US-305 | 参与者取消预订 | 活动开始前可取消本人有效订单；库存只返还一次；重复取消返回同一取消结果；已取消订单保留历史 |
| US-306 | 组织者取消已有预订的活动 | 活动与有效订单在同一事务内取消，库存计数一致；公开活动隐藏，用户仍能从订单查看取消原因；与下单并发不留有效订单 |
| US-307 | 组织者查看本活动预订 | 本人活动下可分页查看预订编号、必要参与者标识、数量及状态；不能读取其他组织者的数据；不暴露密码、令牌等字段 |
| US-308 | 网络重试不造成重复预订 | 同一用户和请求键重试返回同一订单；同键不同参数返回冲突；取消后重试旧创建请求也不能重新占用库存 |
| US-309 | 团队交付可接续的版本 | 空库及 Sprint 2 库升级通过；原认证/活动流程回归通过；三项 CI 与 PR 审查完成；Sprint 4 契约与需求映射完成 |

## 测试重点与完成定义

### 必测场景

1. 新建及旧有活动配置票种，超总容量、负价、零配额、草稿缩容冲突被拒绝。
2. 最后 1 张票并发争抢、跨票种总容量约束、下单中途失败回滚；最终订单数量与库存一致。
3. 同键串行及并发重试只产生一笔订单；异参数冲突；取消后的旧请求重试不再扣库存。
4. 重复取消、并发取消只返还一次；取消活动与下单/用户取消并发，结果无有效残留订单。
5. 草稿、取消、已开始活动及付费票不能完成本轮免费预订；不能伪造用户、金额、活动归属或票种所属。
6. 参与者之间、组织者之间的数据隔离，STAFF 单独角色拒绝，管理员仍遵守本人活动边界。
7. 活动取消后订单历史可读；服务器重启后订单和库存一致。
8. 前端登录返回、数量校验、重复点击、售罄、网络重试、401/403/404/409、空列表及移动视口反馈。
9. 空库建表和 Sprint 2 数据升级成功，用户、角色及活动保留；认证、角色分配、活动搜索/发布/取消回归通过。

### Definition of Done

- US-301–309 逐条记录通过/失败、证据及遗留问题，真实 PostgreSQL 和前后端闭环通过。
- 后端运行 `mvn verify` 及 `RUN_CONTAINER_TESTS=true mvn test`；前端运行 `npm ci`、`npm run typecheck`、`npm test`、`npm run build`，保存实际结果。
- `backend`、`backend-integration`、`frontend` 三项最终提交 CI 通过，至少一名其他组员批准 PR，审查问题解决并按团队流程合并。
- 新增 Flyway 迁移、代码、测试、ERD、数据字典一起交付；不修改已执行迁移。
- Docker 全栈构建、浏览器端到端、重启持久化及移动视口通过；验收报告和截图有可访问的仓库位置。
- 更新 README 当前进度、入口和演示步骤；没有阻断流程、越权、超卖或库存损坏的未解决缺陷。
- Sprint 4 需求清单、支付边界、票券状态、工作人员活动授权及主要任务估算明确。
