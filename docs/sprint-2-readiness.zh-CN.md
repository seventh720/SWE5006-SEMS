# Sprint 2 收尾范围

本记录依据本地实现、已执行测试与 sprint-2-plan.zh-CN.md，不代表所有验收项已完成。

## 已实现

- 活动表、迁移、ERD 和字段文档；空库及 Sprint 1 数据库升级测试。
- 草稿创建、本人列表和详情、编辑、发布、取消。
- 公开活动列表、详情、标题搜索和分页；草稿／取消活动隐藏。
- 组织者角色与归属权限，版本冲突与并发更新保护。
- 对应前端页面、错误反馈、确认操作和按身份划分的 Dashboard。
- 本地后端 38 个测试、前端 27 个测试及构建通过。

## Sprint 2 完成前还需收尾

1. 真实浏览器全链路演示：组织者 A 创建、刷新、编辑、发布；普通用户搜索并查看；组织者 B 无法读取管理详情、编辑、发布或取消；A 取消后公开列表和详情不可访问。保存截图或视频，检查移动端和状态反馈。
2. 补齐认证回归证据：现有认证集成测试包含注册登录、普通用户不可访问管理员接口、管理员查询用户；还应显式验证 `/auth/me`、管理员角色分配、分配后重新登录以及原账号功能。
3. 使用 Docker Compose 验证完整前后端与 PostgreSQL 部署、重启持久化和构建流程；容器集成测试并不等同于完成部署验收。
4. 提交本批 Dashboard 改动，针对最终提交确认 backend、backend-integration、frontend 三项 CI，完成其他组员 PR 审查及合并。此记录未重新查询远端 PR/CI 状态。
5. 按用户故事记录验收结果、遗留缺陷及负责人，完成 Sprint Review / Retrospective 和下轮 backlog。

达到“创建 → 编辑 → 发布 → 公开浏览 → 取消”的真实可演示闭环，并完成以上验证与审查，即可结束本轮。无需为结束 Sprint 2 加入预约、取消预约、票券库存、抢票提醒、支付退款或工作人员签到；这些属于后续迭代。时间筛选和票种契约设计是可选项，不应阻碍收尾。
